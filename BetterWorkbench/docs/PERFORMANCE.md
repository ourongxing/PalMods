# 2026-10-07 冗余清理与性能优化

本次优化保留同工作台范围、库存优先、原生成本计算、五槽后备、动态投入和任务定义兼容行为。

- 原生规划器使用请求内不可变配方表及产物索引。重试只复制库存状态，不再复制整个配方目录；递归只遍历对应产物的候选配方。
- 递归路径使用作用域清理，失败分支退出后恢复路径；候选失败后的库存快照通过移动恢复，避免再次复制。
- 删除预览的额外规划器副本，为单位计划预留容量；删除单次转发的 `plan_request`。
- 当前请求的配方元数据复用一次读取结果，仅重新调用原生研究成本函数。库存、权限和成本仍在每个请求重新查询，不跨请求缓存游戏对象或数据。
- Lua 批量计划直接接管本次求解生成的独立表，删除重复槽位集合和深复制；配方候选选择仅记录数量和 ID。
- 分解槽位扫描每个容器只读取一次完整名称，容量检查只复制计算所需字段；删除冗余回滚状态赋值。
- 默认关闭诊断时延迟加载诊断模块；诊断状态报告完成后停止后台定时回调。
- 构建复用一次游戏文件哈希计算，支持独立构建目录；导入审计支持指定候选 DLL。

历史诊断、离线退款参考及兼容模块仍有测试或工具引用，保留其用途。

## 离线性能对比

MSVC Release，同一合成配方、256 批请求，7 轮各 300 次，取每次请求耗时的中位数。基线由本轮修改前的规划器实现重建，只比较纯 C++ 规划器，不包含游戏反射、库存收集、UI 或 DLL Hook 耗时。

| 场景 | 修改前 ms | 修改后 ms | 耗时下降 |
| --- | ---: | ---: | ---: |
| 2 条配方，复用请求内规划器 | 0.254 | 0.179 | 29.6% |
| 2 条配方，包含规划器构建 | 0.239 | 0.181 | 24.1% |
| 另含 550 条无关配方，复用规划器 | 0.442 | 0.171 | 61.3% |
| 另含 550 条无关配方，包含构建 | 0.564 | 0.481 | 14.8% |

大目录场景用于检查索引和副本开销；游戏接入已有依赖筛选，不能据此推断每次实际请求都会获得同等收益。原始基准代码与结果保存在本机 `.tools/planner-perf`。

## 第二轮：分解刷新与最大数量查询

分解 UI 的一次数量更新现在只读取一次库存快照，单批和当前批数的两次预览共用该快照。快照只存在于同步刷新函数内，下次刷新重新读取；提交分解仍使用事务中的新状态。UI 回归明确断言一次数量更新只有一次快照读取，服务测试覆盖下一次刷新及提交拒绝过期库存。

原生 `can_resolve` 与完整规划共用展开和五槽后备逻辑，省去逐件成本表、累计成本副本及差量扫描。最大数量二分查找直接使用该检查，也不再额外复制规划器或重复转换配方名称。新回归覆盖两条路径的结果一致性，包括混合库存、配方回退、余量、循环、数量边界和 5／64 槽容量。

MSVC Release 合成基准：已有 Part ×5、Ore ×200、Fluid ×170，中间配方每批产出 3 件；在 0–256 内二分查找，最大值均为 170。7 轮各 500 次，单次查询中位耗时从 0.906 ms 降至 0.471 ms，下降约 48.0%。不包含游戏反射和库存收集耗时。代码及原始结果在 `.tools/quantity-perf`。

本轮 75 项 Lua 测试和 2 项原生测试通过，DLL Release 编译及 67 项 UE4SS 导入核对通过。
