# Awakening Trust / 信赖觉醒

0.3.0 · [Steam 创意工坊](https://steamcommunity.com/sharedfiles/filedetails/?id=3824565140)

**觉醒之后才启用信赖度补强。** 未觉醒帕鲁完全使用原版成长。已觉醒帕鲁以原版满级信赖度时的生命、攻击、防御种族值为基准：三项总和不足450的等比例补到450，达到450的保持原样。保留原版满信赖度后的三维比例，每一级、每一项信赖度成长均不低于原版；零信赖度和原始种族值不变。原版觉醒加成另算，不计入450。

棉悠悠觉醒后满信赖度时的有效种族值由125/107/107变为约165.93/142.04/142.04；唤夜兽160/150/146（总和456）不变。这里是未计原版觉醒额外增量的有效种族值，不是最终面板。

## 原理与范围

按每只帕鲁的觉醒状态，在原生属性计算的种族值/信赖度系数阶段补入额外成长，后续等级、潜力、浓缩、帕鲁之魂、词条及取整继续由游戏计算。设原始值B、原版成长g，F=B+10g，S为三项F总和。仅觉醒且S<450时使用新成长`(F×450/S−B)/10`。不修改共享数据表、存档、信赖度经验或觉醒标记，不新增菜单、定时轮询及持久数据。

基线为2026-10-22本机Steam Build 25246127 / v1.0.5.102999。运行时只读取当前角色的“是帕鲁”和“允许捕获”标记，并要求当前个体已觉醒。不查询图鉴编号、角色名称或对应普通形态，不使用固定物种名单。普通与头目均按各自实际数值计算，新增帕鲁沿用相同数据结构即可适用。没有合法图鉴编号但允许捕获的内部角色行也不会额外排除；正常玩法能否获取仍由游戏决定。是否需要增强同样由当前三维与信赖度成长计算。同种未觉醒帕鲁不会因另一只已觉醒而获得加成。

## 安装

内部安装标识统一为 `AwakeningTrust`，显示名称为 **Awakening Trust / 信赖觉醒**。

需要本机匹配版本的UE4SS（SDK 2281fa31），无需PalSchema。关闭Palworld后构建并运行`tools/install_local.ps1`，安装到`<Palworld>/Mods/NativeMods/UE4SS/Mods/AwakeningTrust/`，再完整启动游戏。安装器会拒绝在游戏运行时写入，并备份当前安装、校验部署文件。

正式使用通过工坊安装；本机已切换到正式工坊包。开发构建仍使用本地安装脚本。退出游戏后停用该独立模块可恢复原版成长；不修改存档中的信赖度经验。原生入口受二进制版本及字节校验保护，版本不匹配时保留原版行为。游戏更新后需重新研究和构建；不支持其他同时修改相同原生入口的Mod。若其他Mod修改原始属性/信赖度表，按当前读到的值计算，但未实测此组合。

支持已核对版本的Windows客户端（单机／玩家房主）和Windows专用服务器。服务端使用独立构建，在服务端执行同一套属性增强；联机时请客户端和服务端分别安装对应构建，让属性明细和服务端计算使用相同规则。仅客户端安装不能替代服务端安装。Linux服务器尚未适配。实际验证状态见`docs/VALIDATION.md`，各阶段验收记录分别注明覆盖范围；服务端原生接口检查不等同于完整联机伤害实测。

服务端构建：`python mods/AwakeningTrust/tools/build.py --server`，产物为`dist/AwakeningTrust/server/AwakeningTrust-0.3.0-server.zip`。停服后运行`mods/AwakeningTrust/tools/install_local.ps1 -Server -GameRoot <服务器目录>`，或将对应包内的`Mods/`合并到服务器根目录，再完整重启。两端的DLL不可互换；版本保护会拒绝错误目标。服务端需要自身安装UE4SS，安装器会备份该Mod的旧文件并校验目标程序与安装文件。

## 开发

`tools/generate.py <UAssetAPI导出的原版角色表.json> --audit <本地审计.csv>`生成离线平衡审计。原版资源和研究输出保留在`.build/`，不随源码或发行包分发。`tests/run.py`核对全表目标；原生构建额外运行C++规则测试、二进制入口及UE4SS导入校验。`python tools/build.py AwakeningTrust`构建发行包。
