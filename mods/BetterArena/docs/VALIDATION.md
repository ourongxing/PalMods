# Better Arena 验收记录

环境：Palworld 1.0.5.102999、UE4SS Experimental PW `2281fa31`、PalSchema 0.6.7。2026-10-19 测试均使用独立存档副本，原存档哈希核对不变。

## 当前版本

- 两层入口：竞技场主菜单“扫荡” → 已通关难度 → 立即领取；原版挑战委托保留。
- 默认奖励两倍，倍率限 1～10 整数；玩家段位每日共享次数为 1 / 3 / 5 / 7 / 9 / 11 / 13。
- 启动进入世界后生成 PalSchema 补丁，核对全部 14 组首通／重复奖励后开放扫荡。每个新世界重新应用；写入失败、未就绪、超时均拒领。
- PalSchema 热重载需开启；首次自动开启后需要额外重启一次。蓝图默认值与已存在游戏设置实例的 NPC 基础 RP 同步，原生奖励数组由 PalSchema 修改。

## 验证结果

离线测试覆盖额度刷新、升段补差、回拨时钟、记录隔离、持久预留、背包不足、双击／重入、部分通关、次数耗尽、导航返回及原委托恢复。倍率 1～10 下 Lua／Python 生成的全部奖励和积分补丁一致；另覆盖配置非法值、写入失败、重载超时、切换世界及保留其他 PalSchema 设置。全仓库非原生回归与 29 项共享工具测试通过。

接口／路由实测：保留两倍补丁，仅将配置改成三倍后启动，PalSchema 自动重载全部奖励，NPC 胜利基础分为 150。铂金扫荡 RP 335 → 560（+225）、战斗券 +18、传奇帕鲁球 +4（期望 3～6）；原生横幅文字读回一致，显式 Lua GC 后未崩溃。普通挑战保留原始委托，computer-use 查看预览为帕鲁球 3～6、战斗券 18。

保留三倍补丁、仅恢复两倍配置后重启，14 组奖励自动恢复两倍，NPC 胜利基础分为 100；此轮只读校验。证据位于 `.build/better-arena-autoconfig-20261019/` 的 `live-three-times.txt`、`live-two-times.txt`、`three-times.log` 和 `two-times.log`。原生 Shot 捕获了加载画面，不作为领奖截图证据。

两层真实界面、跨天、升段补差、零次数和重启保存的早期实机证据在 `.build/better-arena-two-level-20261019/`；这些证据使用当时的额度配置。当前奇数额度由离线测试覆盖。用户确认界面恢复正常；普通挑战完整实战及设计图首通实际入包数量未在最终版本重测。

## 保留的接口结论

- 禁用整张原生卡片会显示白块；使用降低透明度和点击校验，保持导航与返回。
- 运行中热加载 Lua 曾导致无响应，未确认具体死锁点。代码和探针安装必须退出游戏；用户授权的自有 JSON 生成交由 PalSchema 热重载。
- 通关记录外层含原生同步对象，不通过 Lua 按值传递，只读反射 `Items`。
- Shipping 的 `Debug_SetArenaRankPoint` 无效；更新实际保存参数的整数字段，并广播原生积分通知。
- 崩溃 `UECC-Windows-7EAC497C4A210C459D46C68240414699_0000` 的栈顶为 UE4SS `+0x271863` 空指针读取，未定位唯一根因。最终移除 Lua 奖励表写入与横幅结构体传参，使用 PalSchema 和标量控件接口；对应领取已记完成，未补发或重置真实额度。修复证据在 `.build/better-arena-crash-0112/`。
