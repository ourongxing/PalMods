# Better Expedition 验收记录

2026-10-19，0.1.0 本地开发版。环境：Palworld 1.0.5.102999，UE4SS Experimental PW 2281fa31。

## 研究证据

`.build/BetterExpedition/` 保存原版 cooked 资源解码、只读反射、字段偏移和原生反汇编；这些不是游戏源代码。已确认原版任务数据、战力与研究耗时计算、奖励倍率、原生完成与取消路径、玩家公会权限检查、奖励容器写入数组布局。

原版完成路径 `0x3022c40` 重算预计完成时间，再比较世界时钟，调用原版奖励生成与写入、召回和状态通知。修改只调整该比较调用的返回时钟；不修改存档中的开始时间，不修改全局时钟。手动结束复用相同完成路径，数量在原版抽取与战力倍率之后按时间比例计算。

## 验收状态

原生构建、支持游戏文件 SHA-256 检查及全部 27 个 UE4SS 导入符号检查通过。编译后的比例与概率取整测试通过；最终 HUD 仅更新数字时间，未初始化、重复刷新及保留原版标题的离线测试通过。全仓库非原生回归、9 项原生测试及 29 项共享工具测试通过。

隔离世界 `49F4E318CF0044C99CFA269459D172AC` 来自原目录 `B810FFA149D3CDCB78C93893E9C42E62` 的关闭游戏后副本；基线哈希位于 `.build/BetterExpedition/original-save-hashes.json`。未在原世界试发奖励。

接口与真实 UI 混合验收：原版页面自动编队后，冰属性任务因 14/20 不足不能出发；改选草原任务、点击自动编队及出发成功，战力 242128/25000，原版奖励预览 984%，原版耗时 1800 秒。仅在测试副本将开始时间回拨 900 秒以加速测试，以结束接口结算，原生记录时间比例 `0.5087355555555556`，状态 InProgress → Reward。

真实奖励容器界面显示 106 个帕鲁矿碎块、45 个普通球、16 个绿色球、241 个矿石、30 个卷轴、25 个帕鲁之魂、25 个食物、35 个蘑菇与 10 个古代文明零件。通过真实“全部领取”按钮入包，绿色球 22 → 38，容器清空；重复结束未再次发奖，返回后可以重选任务。截图 `partial-reward-ui.png`、`partial-reward-collected.png` 及接口记录 `live-partial-and-overdue.txt`、`partial-and-overdue.log` 均位于 `.build/BetterExpedition/`。结算入口本次是接口调用，不能计作真实取消按钮操作已验收。

最终纯数字 HUD 路径已在设施附近运行至完成、领奖与重新出发，进程保持响应，没有文本桥崩溃或更新错误日志；没有取得时间数字控件的独立近景截图，因此其视觉布局不计为完整截图验收。

早期日志中“item submission=80 (0/1=success/no-op)”错误地把无返回值的包装函数当作返回操作结果；该数值不是到账证据。已按反汇编改为 void 签名，改记实际准备的奖励堆数；以上真实容器与入包画面才是到账证据。

## 开发中异常

- `UECC-Windows-62D55CA046DD3AA93140D1A3C36B8EA5_0000`：尚未加载到任务对象时调用状态桥，UE4SS 崩溃；桥和探针增加空参数检查。
- 后续探针过早把标题模板视为真实标题页，启动阶段出现 Lua 栈崩溃。增加真实临时实例筛选后恢复加载，探针之外的原生基线启动正常；没有把该推断作为唯一根因。
- `UECC-Windows-6DE613BB4B085C56861FB29C74CA7953_0000`：新增 HUD Tick 的文本路径在 UE4SS `FText::ToFString` 崩溃，地址 0x70。补充初始化检查后仍复现；移除标题读取后，tooltip 的原生 FText 参数路径仍出现同栈崩溃（`UECC-Windows-0A1D0458401FE5108C85C2BD28C4C8BC_0000`）。最终移除新增 FText 读写，仅调用原有数字计时函数，设施旁及结算后复测保持响应。不能仅凭这些栈断言已定位 UE4SS 内部唯一根因。

尚未验收：按住键盘／手柄执行取消的完整输入动作、时间 HUD 近景布局、严格零时长、满容器、客户端与服务器、经验奖励、未解锁任务的真实 UI、手柄。取消的原生交互路由已验证，但不冒充按键操作已验证。离线与原生代码研究不能替代这些场景。

游戏关闭后，探针归档至 `.build/BetterExpedition/research-final-archive/`，测试世界归档至 `test-world-final-archive/`。原世界 45 个基线文件哈希全部一致，未回滚或修改原世界。发行目录仅含 DLL、数字 HUD 脚本、启用标记和说明，没有测试命令入口；移除了只为研究探针注册状态接口的分支。

移除全部测试工具后再次完整冷启动成功，日志确认 BetterExpedition ACTIVE（revision 102999）；测试 GUID 未被云同步恢复。安装目录仅四个发行文件。原世界 45 个文件哈希最终复核全部一致。

## 2026-10-19 掉帧反馈修复
用户报告严重掉帧。代码及旧运行日志确认远征 HUD Tick 注册了逐帧 Lua 回调，每帧执行状态桥、StaticFindObject 类查找和计时文本更新；这是已识别的高频开销，尚无同场景帧时间对照证明它是全部原因。移除 Tick 注册，改为每秒一次游戏线程刷新；仅首次发现既有 HUD，后续通过对象创建通知跟踪，失效对象移除，隐藏及未初始化控件跳过，任务排队最多一项。奖励／原生完成逻辑未更改。离线覆盖排队去重、隐藏／销毁／重建、异常恢复及禁止逐帧注册和重复全局扫描；奖励测试通过，完整构建与 27 个导入检查通过。用户自行保存并关闭游戏后安装。

修复版安装后完整冷启动，日志显示 ACTIVE；运行日志没有旧 ExpeditionStatusWorldHUD:Tick 注册或本 mod HUD 错误。安装脚本与源码 SHA-256 一致。启动日志归档至 .build/BetterExpedition/performance-fix/after-startup.log。尚未完成同地点、同镜头的帧时间对照及用户掉帧改善确认，不把移除高频路径等同于实测性能恢复。

用户复测反馈性能修复后仍严重掉帧，不能认定逐帧 UI 是唯一原因。按用户要求暂时停用：确认游戏进程全部退出后，将整个本地 BetterExpedition 安装移出 UE4SS Mods 并归档至 D:\Dev\PalMods\.build\BetterExpedition\disabled-installations\20261019-130932。源码、发行包及存档保留；未继续修改或启动游戏。
