# Better Storage / 更好的收纳

基地内沿用原版快速收纳的候选和灰显；野外将主基地 ID 传入原版基地候选接口，使用与基地内相同的筛选和数量规则。保留原版排除列表、确认窗口和服务器转移规则。箱子中没有同类物品时，不会将新物品放入空槽。原版分类、权限及容量检查继续生效。

保留野外选择公会建筑数量最多的主据点（同数量选最近）、普通物品 99,999 堆叠上限，以及同优先级帕鲁搬运优先叠放。

古典大型橱柜与古典书架（`Shelf07_Stone`、`Shelf01_Stone`）改为仅存放设计图。两者共用“设计图箱子容量”设置，默认 360 格；编辑 `BetterStorage/Scripts/config.lua` 的 `BlueprintChestSlots`，可设置 1～4096 的整数，重启游戏或服务器后生效。沿用原版容器权限，普通存入、快速收纳和帕鲁搬运都受此限制。已存放的其他物品保留，可取出；已有容器只扩容不缩容，调低配置不会删除存档中的槽位和物品。载入或新建后最多 5 秒更新，联机由主机或服务器执行。该功能已通过模拟回归，仍需实机验证保存重载与联机同步。

公会箱子共享库存默认扩容至 360 格。编辑 `BetterStorage/Scripts/config.lua` 的 `GuildChestSlots`，可设置 54～4096 的整数，重启游戏或服务器后生效。所有据点的公会箱子仍访问同一份共享库存。

新公会使用配置容量；已有公会通过原版容器扩容方法补充真实槽位，并保留原槽位和物品。容量只增不减：调低配置不会删除已有存档里的格子。扩容由单人、主机或服务器执行，客户端配置不改变服务器容量。每 5 秒在游戏线程检查一次公会库存，覆盖载入存档及新建公会。

公会箱子扩容已通过接口、原生实现核对和模拟回归，本机 180 格扩容已实机确认。保存重载及联机同步仍需实机验收。

野外直接调用原版 CollectQuickStackTargetItemInfos，传入主基地与本地玩家 ID。基地查询限定于背包蓝图执行范围，类名校验按弱引用缓存。

构建：`python mods/BetterStorage/tools/build.py`。

产物：`dist/BetterStorage/BetterStorage-0.1.0.zip`。

退出游戏后，将 ZIP 中的 BetterStorage 文件夹放入 UE4SS/Mods。先禁用 BetterBulkStorage，两个 mod 不能同时启用。

联机的堆叠上限与搬运修改需要主机或服务器加载 DLL；野外收纳沿用服务器验证，联机尚未验收。

2026-10-10：用户确认本机野外收纳及灰显符合主基地规则。
