# BetterWorkbench 原生实现

当前 DLL 版本为 `0.6.2-native-debits`。构建和安装见 [README](../README.md)，调用位置见 [NATIVE_JOB_VIEW.md](NATIVE_JOB_VIEW.md)。

## 制作计划

服务器读取当前工作台配方、玩家科技权限、原生研究成本及原生收集函数返回的容器。
计划优先使用已有中间材料，再递归展开同工作台的缺口；各单位计划共享批内中间产物余量。
整个批量最多 256 批，循环、跨工作台、未解锁配方和非法数量会拒绝。

整批投入用于库存校验、转移和 UI，逐件计划用于完成扣料。配方卡片显示单批需求，详情显示整批需求。
每个穿透任务有独立虚拟配方 ID；虚拟行由 UScriptStruct 深复制，材料身份、槽位和数量表均来自同一计划。
原生材料 map 使用游戏的清空、散列及插入方法构造。

## 输入扩容

匹配的 PalItemContainer 支持最多 64 种投入。容量方法为 `0xdbe790`，扩容实现为 `0x2fa6c00`，
包装函数 `0x2e8d210` 通过 vtable `+0x2b0` 读取容量、`+0x2d8` 请求扩容，并核对原槽指针保留。

成品槽固定为物理索引 5；额外输入使用 6..64。原生转移和按物理位置找槽的调用点在位置 5 插入 None，
验证与退款使用对应的紧凑输入数组。非匹配容器使用五槽策略；超过五种混合投入时最多尝试 64 个单项／双项替换方案。

输入槽函数 `0x300d010` 和索引函数 `0x300e280` 接收构造返回存储，Hook 必须先清零输出头；
异常时返回有效空数组。读取或释放未初始化字段会在 `0x3023e70` 的数组清理路径触发分配器断言。

## 完成扣料

原生完成函数 `0x3012d70` 在 `0x3012f97` 使用固定五槽上限。
Hook 将单位计划的完整移除数组传给事务 `0x2fbc2f0`，限定调用点为 `0x30135d1`。
移除元素为 24 字节：容器 GUID16、物理槽索引4、数量4。

进入完成函数前核对全部投入槽的 GUID、索引、物品和数量。同步调用期间使用线程局部上下文，
产出记录、权限和上下文参数传给原事务。`DEBIT`／`DEBIT_RESULT` 核对槽位前后实际数量，正常完成最多记录 24 次。

## 任务保存与恢复

原生存档保存任务配方 ID、`RequestedProductNum` 和 `RemainProductNum`，单位索引由已完成数量推导。
`BetterWorkbench/Jobs/*.bwj` 保存不可变定义，先持久化再建立任务；校验大小、结构、校验和、游戏版本和工作台 GUID。
定义保留 SRJ4 格式及旧 `SRJ_`／`.srj` 兼容。已存在任务缺少定义时阻止完成。

制作工时使用根配方的原生工时。多人客户端虚拟定义分发尚未接入；扩容槽的存档恢复及部分生产后取消仍需实机验证。

## 二进制与内存约束

- Hook 安装前核对游戏 SHA、入口字节、调用窗口和反射布局。兼容指纹见 [根 README](../../../README.md)。
- 材料条目为 12 字节：名称偏移 0／大小 8，数量偏移 8／大小 4。
- 返回数据在同步回调内复制为拥有所有权的字符串和整数。
- 原生名称查询数组由 FMemory 分配，交由计数函数消费；原生数组不可使用 C++ vector 或 CRT 内存。
- Lua `pcall` 与 C++ 异常处理不能保护原生访问违规。

## 验证

本机 DLL 编译、两项 C++ 回归、177 个参考头文件比对及 67 个运行库导入审核通过。
游戏验收需覆盖混合中间库存、超过五种投入、部分完成后取消、保存重载和成品领取。
构建脚本中的 `--enable-readonly` 用于启用 ABI 审核及原生桥接。
