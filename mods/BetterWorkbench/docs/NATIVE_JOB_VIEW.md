# 原生任务调用位置与 ABI

本机 Palworld 二进制的 RVA，兼容指纹见 [根 README](../../../README.md)。
`tools/inspect_craft_calls.py` 从 PE unwind 的函数起点解码，确认 call 指令。

## 原版制作路径

| 阶段 | 函数 / 调用位置 | 已观察到的行为 |
| --- | --- | --- |
| 建立任务 | worker 0x3005d80，在 0x300611e 调用 0x2fadaa0 | 取得原生单件有效需求；0x3006140 将每个整数数量乘以请求数，然后做整批库存校验。此调用已在碳纤维、电池制作中实机捕获。 |
| 分配输入槽 | 0x3008ea0，在 0x3008f93 调用 GetCurrentRecipe 0x300a0c0 | 通过当前配方材料 ID 顺序定位槽位；随后用原生材料转移函数填槽。需求数组本身不能替代槽位材料身份。 |
| 按材料找槽 | 0x300e300 | 获取当前配方的材料 ID 列表，按匹配 ID 的索引找输入槽。 |
| 判断能继续工作 | 0x300fed0，在 0x301004d 调用 0x2fadaa0 | 检查输入容器中对应 ID 的数量是否满足一件的有效需求，并检查输出槽等条件。 |
| 剩余投入缺口 | 0x300df10，在 0x300df97 调用 0x2fadaa0 | 单件有效需求乘以 RemainProductNum，再减去现有输入容器中相同材料的数量。 |
| 完成一件 | 0x3012d70，在 0x3012e7a 调用材料数量表 0x2fad860 | 枚举前五个输入槽，按实际材料 ID 查询数量表，组装原生消耗请求；同一流程建立输出物品并更新剩余数量。 |
| 执行消耗和产出 | 上述完成函数在 0x30135d1 调用 0x2fbc2f0 | 交由原生物品事务处理消耗请求和产物。需保留此路径，不由 Mod 自行扣槽或添加产物。 |
| 取消清理 | 0x3023e70 | 空配方分支按照实际槽内容进入原生返还清理，已有实机未完成取消观察支持这一路径。 |

## 有效数量表与有效需求列表是两个原生函数

`0x2fad860` 重新从原配方取得材料，调用原生修正项 0x5b，对数量进行游戏自身的整数取整，然后合并到材料数量表。它没有调用已安装桥接的 `0x2fadaa0`。仅 Hook 后者不会覆盖每完成一件时的消耗。

数量表函数的公开 exec 包装位于 `0x2981460`，调用位置为 `0x29815d0`。完成流程调用现场在 `0x3012e7a`：RCX 和 RDX 都是当前模型，R8 是配方 ID，R9 是栈上的数量表对象。反编译器列出的额外参数没有在这一调用现场得到证实，不能直接采用其九参数伪代码签名。数量表内部包含稀疏存储和散列状态，不能按普通材料数组读取。

## 整批材料与逐件材料不能混用

例如请求三个电池，库存只有一个碳纤维，其他碳纤维通过煤炭配方展开：整批会使用碳纤维 1、煤炭 4、喷火器官 2，以及原生计算的电池其他投入。这里的 1、4、2 无法同时表示为整数单件需求乘以 3。

因此整批投入应在原版批量乘法之后、库存校验之前接入。每件完成时则使用该件对应的材料数量表。不能把总材料数量直接写入单件需求，也不能用除法、舍入或重新应用研究系数来适配原版乘法。已持有中间件必须优先使用，不能为了凑出均匀单件需求而忽略它们。

## 任务字段

`SerializeProperties` 位于 `0x301ff70`，先调用基类路径 `0x301fe80`。
模型 `+0x290` 为配方 ID、`+0x298` 为请求数、`+0x29c` 为剩余数；`+0x2b8` 浮点和 `+0x319` 布尔语义待核实。
当前任务定义和恢复方式见 [NATIVE.md](NATIVE.md)。

## 库存调用与数组所有权

worker 在 `0x30061ec` 调用 `0x2fa0020`：RCX 为上下文，RDX 为授权容器数组，R8 为名称数组，R9 为计数输出。
返回条目为 12 字节。函数消费并释放名称数组；调用前复制名称，调用后复制计数。
完整查询中未返回的已请求 ID 可视为未找到匹配材料，失败或部分查询保持未知。

调用前 RSP `+0x58` 是已完成批量乘法的需求数组，`+0x40` 是名称数组。
使用这些栈位置前核对函数入口、乘法及调用窗口，复制数据仅保留字符串和整数。

## 科技与工作台身份

| 接口 | exec / native RVA | 语义 |
| --- | --- | --- |
| IsDeniedRecipe | `0x2ab90e0` / `0x31cc070` | 数据对象的配方禁用数组 |
| IsUnlockCraftRecipe | `0x2b21fd0` / `0x326aa30` | 玩家制作解锁判断 |
| IsUnlockRecipeTechnology | `0x2b22080` / `0x326ac80` | 配方科技判断 |
| GetRecipes | `0x29b8820` / `0x300dde0` | 模型 `+0x2a8` 的配方缓存 |
| GetModelInstanceId | `0x29b8790` | 复制模型 `+0xb0` 的 16 字节身份 |

科技数据对象须属于本次请求玩家，工作台配方名单还需经过解锁及权限检查。
取消 exec `0x29b8100` 经 `0x30058b0` 进入共用 worker `0x3005d80`，传空配方及零数量。

## RecipeView 布局

材料构造器 `0x2fad420` 和 `0x300ced0` 使用 ID 偏移 `+0x24/+0x30/+0x3c/+0x48/+0x54`，
数量偏移 `+0x2c/+0x38/+0x44/+0x50/+0x5c`。存在标记与成本数量分别处理。
副本写入限于 `+0x24…+0x5f`，保留产品、工时和 `+0x70` 的拥有数组；短缓冲、重复 ID、非前缀槽及非法标记拒绝。

## 本地诊断计数

收集器 exec `0x29806c0` 调用 `0x2fa0480`，经 `0x2fa10d0`、`0x2fa0d00` 取得容器，再由 `0x2fa0020` 聚合。
CollectType 2 同时经过玩家及基地分支，基地分支包含 `0x3195250` 等条件检查。
背包数值计数 exec `0x2981060` 调用 `0x2fa3cb0`，基地数值计数 exec `0x2980f80` 调用 `0x2fa3930`。
两类本地计数依赖玩家／基地上下文；服务端制作使用授权容器集合。
