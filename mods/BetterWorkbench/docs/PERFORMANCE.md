# 性能

## 数据复用

- 原生规划器共享请求内不可变配方表及产物索引；候选重试复制库存，递归路径通过作用域清理。
- 配方元数据在单次请求内复用，成本、库存和权限在每个请求重新查询。
- Lua 批量计划接管本次求解产生的独立表；分解槽位扫描为每个容器读取一次名称，容量检查保留所需字段。
- 分解的一次数量刷新共用一份同步库存快照；下次刷新和提交重新读取。
- 最大数量二分查找使用 `can_resolve`，与完整规划共用展开和 5／64 槽策略，仅计算可制作性。
- 诊断模块按配置加载，状态报告完成后停止后台回调。

## 基准

2026-10-07，MSVC Release 合成数据，仅测纯 C++ 规划器。
256 批请求，7 轮各 300 次，取单次请求耗时中位数；基线为优化前实现。

| 场景 | 基线 ms | 优化后 ms |
| --- | ---: | ---: |
| 2 条配方，复用规划器 | 0.254 | 0.179 |
| 2 条配方，包含构建 | 0.239 | 0.181 |
| 另含 550 条无关配方，复用规划器 | 0.442 | 0.171 |
| 另含 550 条无关配方，包含构建 | 0.564 | 0.481 |

最大数量查询使用 Part ×5、Ore ×200、Fluid ×170，中间配方产出 3 件；在 0–256 内二分查找，结果均为 170。
7 轮各 500 次，中位耗时由 0.906 ms 降至 0.471 ms。原始结果位于本机 `.tools/quantity-perf`。

基准未包含游戏反射、库存收集、UI 和 Hook，实际收益需游戏测量。
回归覆盖候选失败恢复、库存副本、两种求解路径一致性、余量、循环、数量边界及同步快照生命周期。
